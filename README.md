# 急救分诊训练小游戏

一个基于 React + TypeScript + Vite 的急救分诊训练工具，用于训练医护人员在紧急情况下快速、准确地对患者进行分诊。

## 功能特性

- **四色通道分诊**：红（紧急）、黄（危重）、绿（非紧急）、黑（死亡/预期死亡）
- **实时资源管理**：氧气、心电图、阿司匹林、颈托、静脉输液、CT 等多种医疗资源
- **患者维度资源绑定**：每次资源消耗明确记录分配给哪位患者，避免评分模糊
- **评分可复算**：完整的操作日志 + 评分证据链（recalcProof），支持事后复盘
- **持久化存储**：未完成局面自动保存，刷新页面可恢复
- **状态流转控制**：开始、暂停、结束、放弃，状态间互斥拦截
- **复盘导出**：支持 TXT / JSON / CSV 格式导出完整操作时间线和评分证据
- **复盘导入**：JSON 格式训练回放包可重新导入，恢复关卡信息、操作时间线、资源-患者绑定、评分快照和校验码
- **冲突处理**：导入时自动检测重复记录、关卡版本不一致、旧包缺失字段等冲突，提供明确处理选项
- **只读复盘**：导入记录进入只读模式，防止修改已结束训练
- **导入日志**：记录每次导入操作的成功/失败、冲突处理方式，可在历史页查看
- **旧存档兼容**：旧版本存档可降级读取和评分
- **教练批注**：在只读复盘页按时间点/患者/全局添加批注、严重程度和处理建议，仅影响本地记录，不修改原始数据
- **批注导出/导入**：批注随回放包一起导出和导入，旧包兼容（导入时批注自动附加）
- **批注冲突处理**：导入时检测本地批注 vs 导入包批注的版本差异、重复目标、已存在批注，提供保留/合并/覆盖选择
- **批注导入日志**：独立记录批注导入冲突处理结果，可查看完整操作记录
- **批注持久化**：刷新页面、重启开发服务后，批注数据从 localStorage 完整恢复
- **训练案例夹**：教练可将任意已结束或导入的回放保存为案例，支持打标签、备注适用场景、设为推荐、归档
- **案例组合筛选**：历史页按标签、关卡、是否含批注、导入来源、推荐、归档状态组合筛选
- **案例只读保护**：案例数据只引用本地记录，不修改原始 session、评分、校验码和只读状态
- **案例导出导入**：案例随 JSON 回放包导出/导入，旧包无案例字段时完全兼容
- **案例冲突处理**：导入时检测本地已有案例、标签差异、归档状态不一致，提供保留本地/合并/覆盖/跳过四种策略
- **案例导入日志**：独立记录每次案例导入的冲突类型、处理策略、新增标签等，可追溯
- **案例持久化**：刷新页面、关闭重开、重启开发服务后，筛选条件、案例标签、归档状态从 localStorage 完整恢复

## 游戏玩法

1. **选择关卡**：从关卡列表中选择一个训练场景（如 `basic-emergency`）
2. **查看患者**：患者队列会显示每位患者的病情描述和分诊建议
3. **分配通道**：点击患者卡片选中，然后点击目标通道（红/黄/绿/黑）
4. **分配资源**：选中患者后，点击对应资源卡片的「消耗」按钮为该患者分配资源
5. **归还资源**：如果资源可复用，选中患者后点击「归还」按钮
6. **暂停/继续**：可随时暂停游戏，暂停期间禁止任何操作
7. **提交评分**：所有患者分诊完成后点击「提交」，查看详细评分和复盘

## 评分规则

总分 = 通道分 + 资源分 + 时间分 + 奖励分 - 扣分项

| 项目 | 说明 | 分值 |
|------|------|------|
| 通道正确 | 患者分配到正确通道 | +100 / 人 |
| 通道错误 | 患者分配到错误通道，按严重程度梯度扣分 | -10 ~ -50 / 人 |
| 资源缺失 | 患者需要的资源未分配 | -10 / 个 |
| 资源滥用 | 消耗性资源分配过多 | -10 / 个 |
| 超时 | 超出关卡时间限制 | -1 / 秒 |
| 暂停惩罚 | 每次暂停 | -20 |
| 全对奖励 | 所有患者通道全对 | +50 |
| 资源高效 | 资源使用率 ≥ 90% 且全对 | +30 |

## 核心架构

### 资源绑定机制

```
ResourceAssignment {
  id: string;           // 资源分配单唯一ID
  patientId: string;    // 分配给哪位患者
  resourceId: string;   // 哪种资源
  assignedAt: number;   // 分配时间
  returnedAt?: number;  // 归还时间（可复用资源）
}
```

**评分双轨制**：
- **Modern 模式**：有 `resourceAssignments` 时，按患者维度聚合统计
- **Legacy 模式**：只有旧的全局 `resourceUsage` 时，按患者顺序依次消费

### 状态拦截

所有修改操作（分配通道、消耗/归还资源）都会经过 `checkStatusAllowsMutation` 校验，在 `PAUSED` / `ENDED` / `ABANDONED` / `IDLE` 状态下被拦截。

### 持久化

- `saveInProgress()`：自动保存未完成局面到 localStorage
- `loadInProgress()`：恢复未完成局面
- `saveHistory()`：保存已提交的评分记录
- `normalizeSession()`：加载时自动补齐缺失字段，兼容旧存档

3. **旧存档兼容**：无 `resourceAssignments` 的旧存档 fallback 算法
4. **三方一致性**：评分、序列化/反序列化（模拟刷新）、TXT 导出三者相互印证

### 导入功能回归测试

测试脚本 `scripts/import-regression.mts` 覆盖以下场景：

1. **正常导入**：完整 ReplayPackage 数据结构校验
2. **旧包兼容**：缺少 patients/resourceSlots 字段的旧导出包可正常解析
3. **重复导入检测**：相同 ID 记录的检测与 KEEP_BOTH/OVERWRITE/SKIP 策略
4. **关卡版本不一致**：导入包版本与本地关卡版本不匹配的检测
5. **跨重启恢复**：模拟 localStorage 序列化/反序列化后 imported/readonly 标记稳定
6. **导入日志持久化**：日志条目含冲突解决记录
7. **缺失字段旧包**：无 scoringRules/patients/resourceSlots 的包检测
8. **不支持的版本号**：未来版本号拒绝
9. **校验码一致性**：相同输入产生相同哈希，不同输入产生不同哈希
10. **导出→导入回环**：数据无损往返
11. **冲突解决策略**：SKIP/OVERWRITE/KEEP_BOTH 行为验证
12. **非法输入**：null/undefined/非 JSON/数组等边界值拦截

## 复盘导入/导出操作说明

### 导出训练回放包

1. 在**结果页**或**历史页**，点击「导出 JSON」按钮
2. 浏览器将下载一个 `.json` 文件，包含：
   - `exportVersion`：导出版本号
   - `level`：关卡完整信息（含 patients、resourceSlots、scoringRules）
   - `record`：训练记录摘要（分数、准确率、用时）
   - `session`：完整操作时间线、资源-患者绑定表、错误记录
   - `scoreResult`：评分快照和 recalcProof 证据链
   - `replayHash`：校验码

### 导入训练回放包

1. 在**结果页**或**历史页**，点击「导入 JSON」按钮
2. 选择之前导出的 `.json` 文件
3. 系统自动校验：
   - 版本号是否受支持
   - 关卡是否存在于本地
   - 患者/资源 ID 是否与本地关卡匹配
   - 是否存在重复记录
   - 校验码是否一致
4. 如有冲突，弹出对话框提供处理选项：
   - **重复记录**：两者都保留 / 覆盖本地 / 跳过
   - **关卡版本不一致**：仍然导入 / 取消导入
   - **旧包缺失字段**：导入（自动补齐）/ 取消
5. 导入成功后，记录标记为「已导入」，进入只读模式
6. 可在历史页点击「导入日志」查看所有导入操作记录

### 只读复盘

- 导入的训练记录自动设为只读，标题显示「复盘查看」
- 只读模式下「重玩」按钮替换为「返回历史」，防止误操作修改已结束训练
- 刷新页面后只读状态从 localStorage 恢复，保持稳定

### 导入失败日志

- 每次导入操作（成功或失败）都会记录到导入日志
- 日志包含：文件名、时间、成功/失败状态、错误详情、冲突处理方式
- 历史页点击「导入日志」可查看全部记录

## 教练批注操作说明

### 概述

教练批注功能允许在复盘回放时，为训练记录添加结构化的教学批注。批注**仅保存于本地复盘记录**，不会修改原始操作时间线、评分结果或校验码，确保训练数据的完整性和可追溯性。

### 添加批注

1. **进入复盘页**：完成训练后进入结果页，或在历史记录中点击查看（只读复盘页同样可用）
2. **找到「教练批注」面板**：位于页面右下方区域
3. **选择添加类型**（点击右上角按钮）：
   - 🕐 **时间点批注**：指定具体秒数，批注与操作时间线的特定时刻关联
   - 👤 **患者批注**：选择具体患者，批注绑定到患者卡片
   - 🏷️ **全局批注**：对整场训练的总体评价
4. **填写批注内容**：
   - **严重程度**：轻微 / 一般 / 严重 / 致命（四色分级）
   - **批注内容**：描述观察到的问题或亮点
   - **处理建议**：建议如何改进（选填）
5. 点击「添加批注」完成

### 查看与编辑批注

- 批注按时间倒序显示在面板中，显示严重程度色标、目标类型、内容和建议
- 点击 ✏️ 编辑图标可修改批注（严重程度、内容、建议）
- 点击 🗑️ 删除图标可删除批注
- 按时间点添加的批注会同步显示在「操作时间线」的对应时刻下方

### 批注与历史列表

- 历史列表中每条记录会显示批注数量标签 `💬 批注 N`
- 展开历史记录后可快速跳转查看详细批注

### 批注导出（随回放包一起）

1. 在结果页或历史页点击「导出 JSON」
2. 若该记录含批注，导出面板会显示提示：「含 N 条教练批注，导出 JSON 时将一并打包」
3. 导出的 JSON 包含额外字段：
   - `annotations`：批注数组（若为空则不写）
   - `annotationVersion`：批注结构版本号
4. 「导出文本」(TXT) 同样会在文件末尾附上完整批注列表

### 批注导入与冲突处理

#### 正常导入（无冲突）

- 导入新回放包且本地无批注时，批注直接附加到对应记录
- 导入旧版本回放包（无 annotations 字段）时保持无批注状态，完全兼容

#### 冲突检测

系统在导入时自动检测以下冲突并弹窗提示：

| 冲突类型 | 触发条件 |
|---------|---------|
| **本地已有批注** | 同一记录本地已有 M 条，导入包带 N 条 |
| **相同目标重复** | 导入包与本地存在同一时间点/同一患者的批注 |
| **批注版本差异** | 导入包的 annotationVersion 与本地版本不一致 |

#### 冲突解决选项

弹窗提供四种明确的处理方式：

1. 🛡️ **保留本地批注**：忽略导入包批注，本地批注原样保留
2. 🔀 **合并（推荐）**：保留本地批注，并追加导入包中不重复的新批注
3. 🔄 **用导入包覆盖**：删除本地所有批注，用导入包批注替换
4. ⏭️ **跳过批注导入**：完全不处理批注部分

所有选择都会写入**批注导入日志**，包含：处理方式、冲突类型、本地/导入数量、最终数量。

### 批注导入日志

- 每次导入（无论成功/失败/跳过）都会记录独立的批注导入日志
- 可通过浏览器控制台检查 `localStorage['triage:annotation-import-log']` 查看完整 JSON

### 跨刷新与重启恢复

批注数据存储在浏览器 localStorage 中：

- ✅ 刷新页面：批注从 `triage:annotations` 键完整恢复
- ✅ 关闭标签再打开：批注仍然存在
- ✅ 重启开发服务（npm run dev）：浏览器数据不受影响
- ✅ 合并结果持久化：冲突合并后立即写入 localStorage，刷新后合并结果稳定
- ✅ 只读限制稳定：导入记录的只读标记与批注数据独立存储，互不影响

## 训练案例夹操作说明

### 概述

训练案例夹功能允许教练将任意已结束或导入的回放保存为结构化案例，用于教学回顾、典型案例积累和场景归档。案例数据**独立存储于 localStorage**，通过 `recordId` 引用本地训练记录，不修改原始 session、评分结果、校验码和只读状态。

### 保存为案例

1. 进入**历史页**（点击首页「历史成绩 & 案例夹」或复盘页「返回历史」）
2. 在任意训练记录卡片右侧点击「存为案例」按钮
3. 在弹出的对话框中填写：
   - **案例标题**（必填）：给案例一个简短明确的名称，如「典型胸痛分诊案例」
   - **适用场景/备注**：描述教学要点、适用学员水平、注意事项等
   - **标签**：用逗号分隔，如 `胸痛, 初学者, 高分参考`
   - **设为推荐**：勾选后卡片会显示金色边框和 ★ 标记，排序更靠前
   - **归档**：勾选后卡片半透明显示，仍可通过筛选器找到
4. 点击「保存案例」完成

### 编辑与删除案例

- 历史页中已有案例的记录显示「编辑案例」按钮

- **推荐案例**：金色边框 + ★ 推荐徽章，分数色块为金橙渐变

### 案例导出（随回放包一起）

1. 在结果页或历史页点击「导出 JSON」
2. 若该记录存在案例，导出的 JSON 自动附加：
   - `caseInfo`：完整案例对象（title、description、tags、recommended、archived 等）
   - `caseVersion`：案例结构版本号（当前 v1）
3. 无案例的记录不附加上述字段，保持最小化导出

### 案例导入与冲突处理

#### 正常导入（无冲突）

- 导入含案例的新回放包且本地无案例时，案例直接附加（source 标记为 `IMPORTED`）
- 导入旧版本回放包（无 `caseInfo` 字段）时保持无案例状态，完全兼容

#### 冲突检测

系统在导入时自动检测以下冲突并弹窗提示：

| 冲突类型 | 触发条件 |
|---------|---------|
| **本地已有案例** | 同一记录本地已保存案例，导入包也携带案例 |
| **案例标签不一致** | 本地与导入包的标签集合存在差异 |
| **归档状态不一致** | 本地与导入包的 archived 布尔值不同 |
| **案例版本差异** | 导入包的 caseVersion 与本地版本不一致 |

#### 冲突解决选项

弹窗提供四种明确的处理方式（默认推荐「合并标签」）：

1. 🛡️ **保留本地案例**：忽略导入包案例数据，本地案例完全不变
2. 🔀 **合并标签（推荐）**：保留本地案例基础上，合并两侧标签（取并集去重）；推荐状态取 OR（任一为 true 即为 true）；归档状态取 AND（同时为 true 才归档）；导入标题/描述非空时覆盖本地
3. 🔄 **用导入包覆盖**：删除本地案例，用导入包案例完整替换（source 改为 `IMPORTED`）
4. ⏭️ **跳过案例导入**：完全不处理案例部分，保持现状

所有选择都会写入**案例导入日志**，包含：处理策略、冲突类型列表、本地/导入是否含案例、最终状态、新增标签等。

### 案例导入日志

- 每次案例导入操作（无论成功/失败/跳过）都会记录独立日志
- 可通过浏览器 DevTools 检查 `localStorage['triage:case-import-log']` 查看完整 JSON
- 日志条目包含：文件名、时间、成功/失败、冲突类型、解决策略、标签变化等

### 跨刷新与重启恢复

所有案例相关数据持久化于浏览器 localStorage：

| 数据类型 | Storage Key | 恢复保证 |
|---------|-------------|---------|
| 案例数据 | `triage:cases` | ✅ 刷新/关闭重开/重启 dev 服务后完整恢复 |
| 案例导入日志 | `triage:case-import-log` | ✅ 最多保留 100 条 |
| 历史页筛选条件 | `triage:history-filters` | ✅ 所有 8 个筛选维度自动恢复 |
| 训练记录（原始） | `triage:history` | ✅ 案例仅通过 recordId 引用，不修改原始数据 |

### 测试覆盖范围

案例测试脚本 `scripts/case-regression.mts` 覆盖以下场景（共 11 个用例）：

1. **案例 CRUD**：新增 → 读取 → 编辑（验证版本号自增）→ 删除，每步验证字段完整性
2. **标签聚合与状态计数**：多案例标签去重聚合、推荐案例数、归档案例数统计正确
3. **导出/导入回环**：导出含案例 JSON → 重新解析 → 验证 title/description/tags/recommended/archived 全部字段完整
4. **冲突四种策略**：
   - KEEP_LOCAL：本地案例不被修改
   - MERGE：标签并集去重、推荐 OR、归档 AND、版本号自增
   - OVERWRITE_LOCAL：本地案例被完整替换，source 变为 IMPORTED
   - SKIP：本地案例不变，日志记录成功=false
5. **冲突类型检测**：标签差异、归档差异、版本差异分别触发对应冲突类型
6. **旧包兼容**：v1 导出包（无 caseInfo/caseVersion）导入后案例数为 0，不报错
7. **跨重启恢复**：MockStorage JSON 序列化→反序列化后，案例、导入日志、全部 8 项筛选条件完整恢复
8. **只读限制验证**：批量创建 5 个案例后，原始 session/scoreResult/校验码字节级不变，storage 中仅出现案例相关键
9. **案例导入日志**：冲突处理后日志条目含 id/timestamp/fileName/resolution/conflicts/tagsAdded 等全部字段
10. **筛选与状态一致性**：批量创建 5 个不同配置的案例，getAllCases/getCaseTags/推荐计数/归档计数与预期一致
11. **MERGE 边界场景**：导入标题/描述为空字符串时，保留本地标题和描述，不被空值覆盖

## 复算验证流程

1. 游戏操作产生 `operationLog` 和 `resourceAssignments`
2. 提交时 `calculateScore()` 生成 `recalcProof` 证据链
3. 复盘导出 `exportReplayTXT()` 包含「资源-患者绑定表」
4. 三者可独立相互校验，确保评分公平透明
